# 招聘 JD 六字段标注规范 v1

版本：v1.0  
适用数据：Chinese-SkillSpan v0.1.3 抽取的 600 条句子与后续补充语料  
标注单位：连续原文片段，字符级起止偏移  
标签集合：`技能`、`学历`、`经验年限`、`岗位名称`、`语言能力`、`知识领域`

## 1. 总原则

本规范沿用 Chinese-SkillSpan handbook B 的“语义不变则尽量短、完整性先于长度”原则。每个标签只覆盖原文中能够独立表达该字段的最短完整片段，不补字、不改写、不跨字段合并。所有偏移采用 Python 字符串语义：从 0 开始计数，右端不包含，满足 `text[start:end] == span`。

本轮采用平坦实体层。同一字符位置只允许一个标签，不允许嵌套或交叉。软性描述不进入六字段 schema；遇到无法裁决的边界或类型，记录为 `adjudication_required`，不能直接作为人工 Gold。

## 2. 字段定义

| 字段 | 定义 | 边界规则 | Chinese-SkillSpan 对应 |
|---|---|---|---|
| 技能 | 具体硬技能、工具、技术、可执行职业动作 | 工具名只框名称；动作短语保留必要的动作和对象 | S |
| 学历 | 最低学历层级要求 | 框学历层级本身；“本科及以上”框“本科” | K 的一部分 |
| 经验年限 | 明确的工作年限要求 | 数值、范围、单位及“以上/以内”等必要限定一起框 | K 的一部分 |
| 岗位名称 | 招聘职位的完整名称 | 框完整职位名；公司名、地点和待遇不进入跨度 | 无直接对应 |
| 语言能力 | 外语语种、水平、考试或证书要求 | “英语六级”“日语N2”等完整表述一起框 | L |
| 知识领域 | 专业知识、学科、理论领域或行业知识 | 只框领域名词；不把修饰动作和软性能力一起框入 | K |

## 3. 正例与反例

| 字段 | 原文与正例 | 反例 | 反例原因 |
|---|---|---|---|
| 技能 | “熟练使用 PyTorch” → 框“PyTorch” | 框“熟练使用 PyTorch” | 修饰语不属于最小技能名 |
| 技能 | “维护IT基础设施” → 框“维护IT基础设施” | 只框“维护” | 丢失必要对象，语义不完整 |
| 技能 | “会用 SQL 查库” → 框“SQL” | 框“会用 SQL” | “会用”是触发语，不应进入跨度 |
| 技能 | “负责接口对接” → 框“接口对接” | 框“负责接口对接” | “负责”是职责外壳，不单独表达技能 |
| 技能 | “熟悉 Python 和 MySQL” → 分别框“Python”“MySQL” | 框“Python 和 MySQL” | 两个可独立识别的工具不应合并 |
| 学历 | “本科及以上学历” → 框“本科” | 框“本科及以上学历” | 要求层级是“本科”，其余是条件或外壳 |
| 学历 | “硕士优先” → 框“硕士” | 框“硕士优先” | “优先”不是学历层级 |
| 学历 | “大专以上” → 框“大专” | 框“以上” | 单独层级词没有完整含义 |
| 学历 | “博士研究生” → 框“博士研究生” | 框“博士” | 原文的完整学历名不能被截短而改变表述 |
| 学历 | “计算机本科” → 框“本科” | 框“计算机本科” | “计算机”是专业知识领域，应单独处理 |
| 经验年限 | “3年以上后端开发经验” → 框“3年以上” | 框“3年” | 丢失“以上”会改变要求 |
| 经验年限 | “1-3年工作经验” → 框“1-3年” | 框“1-3” | 缺少单位，数值语义不完整 |
| 经验年限 | “两年以上” → 框“两年以上” | 框“两年” | 丢失最低年限限定 |
| 经验年限 | “具有5年研发经历” → 框“5年” | 框“5年研发经历” | 经验活动不是年限字段 |
| 经验年限 | “应届毕业生” → 不框经验年限 | 框“应届毕业生” | 这是身份或招聘对象，不是明确年限 |
| 岗位名称 | “招聘Java开发工程师” → 框“Java开发工程师” | 框“招聘Java开发工程师” | “招聘”不是职位名称 |
| 岗位名称 | “岗位：数据分析师” → 框“数据分析师” | 框“岗位” | 栏目词不是岗位名称 |
| 岗位名称 | “高级产品经理” → 框“高级产品经理” | 只框“产品经理” | 原文含级别且该级别属于职位名 |
| 岗位名称 | “IT工程师(某公司)” → 框“IT工程师” | 框完整括号公司名 | 公司名不是职位名称 |
| 岗位名称 | “负责后端开发” → 不框岗位名称 | 框“后端开发” | 职责活动不能自动当作职位名 |
| 语言能力 | “英语六级” → 框“英语六级” | 框“英语” | 丢失等级，语言要求不完整 |
| 语言能力 | “CET-6” → 框“CET-6” | 分别框“CET”和“6” | 证书名是一个完整表述 |
| 语言能力 | “日语N2” → 框“日语N2” | 框“N2” | 缺少语种，含义不完整 |
| 语言能力 | “英语可作为工作语言” → 框“英语可作为工作语言” | 框“工作语言” | 脱离语种后无法表达语言要求 |
| 语言能力 | “沟通能力强” → 不框 | 框“沟通能力”为语言能力 | 沟通是跨行业软技能，不属于外语能力 |
| 知识领域 | “机器学习” → 框“机器学习” | 框“负责机器学习” | 动作外壳不应进入领域名 |
| 知识领域 | “自然语言处理相关理论” → 框“自然语言处理相关理论” | 只框“自然语言处理” | 明确要求理论时，完整知识短语不可截短 |
| 知识领域 | “计算机网络” → 框“计算机网络” | 框“熟悉计算机网络” | “熟悉”不是知识领域 |
| 知识领域 | “有金融行业经验” → 框“金融” | 框“行业经验” | 要求的是领域知识，泛化经验词不是领域 |
| 知识领域 | “具有数据分析能力” → 根据语境判断 | 无条件框“能力” | “能力”是泛化中心，可能属于技能或软技能 |

## 4. 边界裁决规则

1. 先判断范围，再判断类型。只有属于候选人能力、知识、资格、岗位或要求的连续原文才可能进入实体。
2. 能无损拆成两个独立实体时分别标注；拆分后丢失必要动作、对象、层级或限定语时保留最短完整跨度。
3. 剥除“熟悉、掌握、了解、具备、负责、优先”等触发语，除非该词是完整原文语义不可删除的组成部分。
4. 工具名按语境区分。作为岗位工具或实际运用对象时标“技能”；明确要求课程、原理、语法或基础知识时，完整短语标“知识领域”。
5. 语种、语言水平和语言考试整体标“语言能力”；非语言职业认证归“知识领域”。
6. 学历名标“学历”，明确年限标“经验年限”，其他领域名标“知识领域”。同一短语不重复标注类别。
7. 同一位置只保留一个标签。若“Python”同时可解释为技能和知识领域，按用户给定规则优先标“技能”，并在质检记录中保留歧义说明。
8. 结果、目标、KPI、福利、公司荣誉和岗位职责范围本身不标；只标能够对应到 schema 的原文片段。

## 5. 不标注清单

- “沟通能力强”“有责任心”“团队合作”“学习能力”等软技能和人格特质。
- “岗位职责”“任职要求”“优先考虑”等栏目词或触发语。
- “提升用户体验”“保证业务增长”等结果、目标或 KPI 从句。
- 公司名称、公司规模、办公地点、薪资、福利和招聘流程。
- 不属于候选人的产品能力、系统属性、公司技术优势或行业宣传。
- 嵌套实体、交叉实体和无法在原文中连续定位的补写片段。
- 乱码、关键上下文缺失或无法裁决的记录；这些记录单独放入疑难队列。

## 6. 标注状态与质检口径

每条记录使用以下状态之一：

| 状态 | 含义 |
|---|---|
| `candidate` | 机器学习或规则生成的候选，等待复核 |
| `silver_reviewed` | 经规则和结构复核，可作为 Silver 使用 |
| `adjudication_required` | 范围、边界或类型仍不确定 |
| `human_gold` | 真实人工逐条确认，可用于 Gold |

本周产出的 `label_studio.json` 属于 `silver_reviewed` 初始数据，不代表人工 Gold。真实人工复核后应另存版本，并保留复核人和修改理由。

## 7. Label Studio 项目配置

```xml
<View>
  <Text name="text" value="$text"/>
  <Labels name="label" toName="text">
    <Label value="技能" background="#166534"/>
    <Label value="学历" background="#1D4ED8"/>
    <Label value="经验年限" background="#7C3AED"/>
    <Label value="岗位名称" background="#B45309"/>
    <Label value="语言能力" background="#BE123C"/>
    <Label value="知识领域" background="#0F766E"/>
  </Labels>
</View>
```

标签名必须与 `schema_v1` 和训练转换参数完全一致。预标注中的 `from_name` 固定为 `label`，`to_name` 固定为 `text`。
