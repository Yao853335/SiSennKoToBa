# 技术选型说明

## 结论

项目以 PaddleNLP UIE 作为招聘JD信息抽取主引擎，以 crownpku/Information-Extraction-Chinese 作为传统NER/RE方法的原理参照和后续对比基线。

## 主引擎选择UIE的原因

1. UIE通过自然语言Schema定义抽取目标，可以在没有领域训练数据时形成零样本基线。
2. 本项目已在CPU上完成 `uie-base` 的模型加载、五字段JD抽取和10条文本测试。
3. 同一模型可通过Schema适配岗位、技能、学历、经验和地点，后续还能扩展到关系与事件任务。
4. PaddleNLP提供从标注、微调、评估到Taskflow定制的完整流程，便于第8至10周继续迭代。

## crownpku项目的角色

该项目包含两个传统子任务：

| 子任务 | 数据与标签 | 模型 |
|---|---|---|
| NER | 字符级IOB1标签，实体为ORG/PER/LOC | IDCNN+CRF或biLSTM+CRF |
| 关系抽取 | 实体1、实体2、关系、句子以Tab分隔，12类关系 | biGRU+词级/句级双注意力 |

它适合说明传统监督式实体识别和关系分类的训练方式，但其标签体系固定、依赖旧版TensorFlow，训练成本高于本周CPU零样本目标，因此不作为主流程。

## CPU与GPU边界

| 操作 | CPU | 后续安排 |
|---|---|---|
| UIE零样本推理 | 已验证可行 | 本周主流程 |
| Schema设计与人工核查 | 可行 | 第7至10周持续进行 |
| 数据标注与格式转换 | 可行 | 第8周 |
| 小规模微调 | 可做冒烟测试 | 优先安排GPU稳定训练 |
| crownpku TensorFlow训练 | 不作为本周任务 | 留作后续对比 |

## 定稿

本周技术路线为“UIE零样本基线 + crownpku原理参照”。不使用传统模型替代UIE主流程，也不在本周提前实现关系抽取与图谱界面。
