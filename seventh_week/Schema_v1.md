# Schema v1

## 字段定义

```python
schema = ["岗位名称", "技能", "学历", "经验要求", "工作地点"]
```

| 字段 | 定义 | 示例 |
|---|---|---|
| 岗位名称 | 招聘岗位标准名称 | 数据分析师、产品经理 |
| 技能 | 完成岗位工作所需的技术、工具或能力 | SQL、Python、沟通能力 |
| 学历 | 最低学历层次 | 本科及以上、大专及以上 |
| 经验要求 | 工作年限 | 3年以上、1至3年 |
| 工作地点 | 城市或工作区域 | 上海、杭州 |

## Schema措辞对照

在前4条JD上比较三种方案：

- A：技能要求、学历要求、经验要求。
- B：技能、学历、工作年限。
- C：技术要求、学历要求、工作经验。

结果：

- A方案学历、经验边界清楚，但“技能要求”会重复抽出学历和经验。
- B方案能抽出SQL、Python、Excel等技术词，但“工作年限”没有输出。
- C方案“技术要求”仍会混入学历和经验。
- 最终采用短字段“技能”加完整字段“经验要求”的组合。

## 10条零样本结果

| 字段 | 结果 | 观察 |
|---|---|---|
| 岗位名称 | 10/10正确 | 起止位置准确，概率多数高于0.94 |
| 技能 | 2/10部分命中 | 可抽SQL、Python、Excel等英文技术词，其他技术栈大多未召回 |
| 学历 | 10/10正确 | 本科、硕士、大专及以上均可识别 |
| 经验要求 | 10/10正确 | 1年以上、2年以上、3至5年均可识别 |
| 工作地点 | 10/10正确 | 城市名全部命中 |

10条文本平均非空字段数为4.2/5，模型加载后的推理耗时为13.815秒。

## 误差分析

技能字段的问题主要是覆盖不足。数据分析师样例抽到SQL、Python、Excel，但漏掉Tableau和Power BI；算法、前端、后端、测试、嵌入式和运维样例的技术栈基本未被召回。使用“技能要求”或“技术要求”时，模型还会把学历、经验误认为技能。

学历和经验之所以稳定，是因为表达集中在“本科及以上”“硕士及以上”“1年以上”等有限模板。工作地点则受益于城市名称的常见实体特征。

## 下一版方向

第8周将技能进一步拆分为技术名称、工具名称和通用能力，并保留原文完整片段；第9至10周比较零样本与微调后的技能召回率，再决定采用多字段Schema还是关系Schema。
