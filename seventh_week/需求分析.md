# 需求分析

## 场景与目标

系统面向招聘JD信息抽取。输入为一段招聘文本，输出岗位名称、技能、学历、经验要求和工作地点等结构化字段，为后续岗位技能图谱提供数据。

阶段一只验证“文本输入 → Schema定义 → UIE零样本抽取 → 人工核查”的闭环，不实现Web界面、数据库和图谱。

## 用户与使用方式

课程设计者通过Python脚本检查字段结果、调整Schema并记录错误；课程评审者通过报告、截图和原始JSON检查实验过程。阶段二才会增加标注数据与微调实验。

## 功能范围

| 范围 | 内容 |
|---|---|
| 本周范围内 | 纯文本JD；五字段实体抽取；保留起止位置与置信度；10条样例测试与误差记录 |
| 本周范围外 | 关系抽取、图谱、Streamlit界面、数据库、用户系统、在线部署 |
| 后续范围 | 第8至10周数据标注、微调、Schema优化；第11周岗位-技能关系与图谱 |

## 验收标准

1. 在10至20条文本上至少稳定抽出1至2个合理字段。
2. 每条结果可追溯到原文位置、Schema、模型和运行设备。
3. 对未抽出或抽错的字段记录原因。
4. 不以字段“有输出”替代“语义正确”。

## 当前结果

- 岗位名称：10/10正确。
- 学历：10/10正确。
- 经验要求：10/10正确。
- 工作地点：10/10正确。
- 技能：2/10部分命中，技术栈覆盖不足。
- 平均非空字段数：4.2/5。

最低验收线已经达到，但技能字段仍不能直接用于最终结构化入库。

## 风险与控制

| 风险 | 控制 |
|---|---|
| 技能粒度不统一 | 第8周统一定义技术名称、工具和通用能力 |
| 学历、经验污染技能字段 | 比较字段措辞并补充标注 |
| 10条样本不足以代表全部JD | 第8周扩大到500至1000条并抽样复核 |
| GPU不可用影响训练 | 保留CPU零样本基线和误差分析，训练按硬件条件安排 |
