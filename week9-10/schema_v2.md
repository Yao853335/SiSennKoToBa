# Schema v2 调优说明（第 10 周）

## 1. 调优对象与依据来源

依据第 9 周 `evaluate.py --debug`（及同口径 Taskflow 评估 `eval_finetuned_v1.json`）
的逐字段 F1，选取最低的两个字段做**最小改动**，不全面重写 schema：

| 字段 | v1 测试集 F1 | 排名 |
|---|---:|---|
| 岗位名称 | 0.21053 | 最低（调优对象 1） |
| 技能 | 0.32000 | 次低（调优对象 2） |
| 知识领域 | 0.33043 | 第三（不动） |
| 语言能力 | 0.57143 | 不动 |
| 学历 | 0.80000 | 不动 |
| 经验年限 | 0.80000 | 不动 |

## 2. 错误证据（逐样本归类，共 360 行/60 条文本）

### 岗位名称（13 gold，TP 2 / FP 4 / FN 11）

- **FN（7 条）+ 边界错误（6 条）占主导**：漏抽的"金融研究员""商务经理""分公司总监""区域总监"
  均为字面规整的职位词，微调模型仍不敢抽——说明触发 prompt「岗位名称」与 JD 原文里
  "职位名称：/关键字：/岗位描述："等表述的关联弱；
  边界错误集中在模型取"微信小程序软件（南京）服务中心销售专员"这类完整头衔、
  而 silver 标注拆成"服务中心销售专员"——**字段语义边界在标注端就不一致**（同一短语，
  一处拆细、一处取全）。

### 技能（124 gold，TP 32 / FP 44 / FN 92）

- **FN 92 中约 20 条是违反第 8 周标注规范"完整性先于长度"的残缺 gold**：
  "挖掘潜在""笔试—""面试—""构建完善""提交开发""区域""收取钥匙"——
  这些 span 丢失了必要宾语/动作对象，模型按常见语言模式补全后必然判 FP；
- 另外 FN 覆盖"用户调研""解决方案""数据分析"等**软性/通用能力词**，
  零样本模型天然不把它们当"技能"；
- FP 44 里"Photoshop""GrowingIO智能算法产品化4""数据化运营"等与"知识领域/岗位职责"
  的边界争议大——即执行文档预警的"技能同时涵盖工具与软技能时边界模糊"。

## 3. v1 → v2 改动（按执行文档优先级 1、2）

| 改动 | v1 | v2 | 优先级依据 | 预期作用 |
|---|---|---|---|---|
| 字段名改常见词 | 技能 | **专业技能** | 文档方向(1)：schema 字段名即 prompt，用高频限定词提升召回 | "专业技能"比裸"技能"更贴近 JD 中"技能要求：/专业技能"表述，且显式排除软技能歧义 |
| 字段名改常见词 | 岗位名称 | **招聘职位** | 文档方向(1)：同上 | "招聘职位"是招聘域最高频触发词（"职位/招聘"），期望缓解规整职位名的漏抽 |
| 其余四字段 | 学历 / 经验年限 / 语言能力 / 知识领域 | 不变 | 文档要求只动 F1 最低的 1~2 个 | 保持对照实验局部性 |

说明：文档方向(2)提到的"拆分为编程语言/框架工具"未采用——本测试集技能 gold 124 条中
约 60% 是职责动作短语而非工具名，拆分无法解决主要矛盾（标注一致性），且违反"只动 1~2 个
字段"的最小改动原则；方向(3)的合并亦不采用，技能/知识领域虽边界争议大但合并会破坏与
v1 的可比结构。

## 4. 执行方式（守住红线三：重新生成训练数据 + 重新微调）

schema 编码在训练数据 prompt 中，因此**必须回到第 8 周 label_studio.py 的转换链**：

```bash
python scripts/regenerate_data_v2.py --rename "技能=专业技能" --rename "岗位名称=招聘职位"
# 输出 data_v2/{train,dev,test}.txt，seed=42 / splits=0.8,0.1,0.1 / negative_ratio=5
# 与 v1 完全一致；校验结果：60 条测试文本集合 texts_identical=true，
# gold span 边界集合与 v1 等价（label_set_mismatch=0, gold_span_mismatch=0）
```

随后以与 v1 相同的超参微调 `checkpoint/uie_jd_v2`，再在同一测试文本集（data_v2/test.txt）上
用 `evaluate_finetuned.py --schema <v2六字段> --label_map "专业技能=技能" --label_map "招聘职位=岗位名称"`
评估，把结果映射回 v1 字段空间做逐字段对比。

## 5. 预期与风险

- 预期：两个改动字段的召回提升（prompt 更贴原文措辞），F1 上行；
- 风险：字段改名对负例 prompt 分布的影响是全局的，可能扰动未改字段的注意力分配
  ——因此对比二除"被改字段"外，也如实报告**未改字段的联动变化**并解释
  （TP 变化 ±1~2 属小样本随机波动；系统性变化需结合错误分析）。
